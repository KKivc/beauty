# 实施计划

1. 新增并验证 `prepareBeautyContext`
   - 生成全图裸露皮肤、人脸皮肤与五官保护 mask，并记录尺寸和人脸框。
   - 实现旋转级联候选、解剖一致性筛选与结构回退。
   - 增加断开手臂、近似肤色背景、偏转脸和 context 校验测试。

2. 重构美颜核心
   - 为 `beautifyImage` 增加可选 context，改为 Y/Cb/Cr 多尺度结构、色斑和纹理处理。
   - 保持低频结构、最大档约 20% 高频纹理和受保护五官；美白仅使用皮肤内有界单调曲线。
   - 为 `recommendBeautyParams` 增加可选 context，并只统计 `faceSkinMask`。

3. 接入 GUI 缓存
   - 增加 private `beautyContext`，在人脸检测后准备并缓存。
   - 拖动、最终刷新与一键美颜传递缓存；重置保留，新图/失败清空。
   - 保持现有耗时指标只统计一次 `beautifyImage` 调用。

4. 自动化和参考图验证
   - 扩展算法测试：单调性、70% 雀斑衰减、10% 纹理下限、80% 低频结构、85% 五官梯度、色度斑点及非皮肤保护。
   - 扩展 GUI/上下文测试，验证缓存生命周期和向后兼容。
   - 运行两个现有测试套件、新增测试、`checkcode` 与 `git diff --check`。
   - 在不提交图片的前提下，用 `80/80r`、`81/81r` 做局部纹理、五官和皮肤范围对照，并测量缓存预览耗时。

## 风险与回滚点

- 全图皮肤分割可能误选肤色背景；连通域与严格独立区域筛选必须单独验证。
- 级联五官检测对偏转脸不稳定；不得绕过结构回退或将低置信候选强行作为保护区。
- Y/Cb/Cr 强磨皮可能造成塑料感或色块；频率保留下限和结构/梯度断言是合并门槛。
- GUI context 生命周期错误会复用旧图片 mask；所有清理路径必须同步清空。
